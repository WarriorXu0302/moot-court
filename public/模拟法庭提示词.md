# 任务

设计一个教师端和学生端打通的模拟法庭教学系统。学生可以扮演**辩护人、公诉人、审判长**三种角色，三条角色的训练支线流程完全不同，不能简化和公约，必须分别设置。遇到所有需要思考的场合都调用豆包2.0 pro（模型 doubao-seed-2-0-pro，关闭推理 thinking=disabled），ai思考时显示"发言角色正在思考…"的等待态，且此等待态不影响正常查看和使用界面。所有页面必须支持响应式布局（桌面端多栏、移动端单栏堆叠），对话记录的增长不能改变页面长度，而是设置滚动（页面外层框架固定不滚、各内容栏自带独立滚动区，任何一栏都不允许出现"外层禁滚动+内层无滚动区"的组合）。所有对话，上下文和提示词都非常长，必须建立命中缓存的机制。所有对话可以查看文本，也可以听ai配音，ai配音可以选择关闭。所有文本必须使用流式输出。

## 文本/语音双模式（核心交互设定）

庭审各环节页面支持**文本模式与语音模式一键切换**，两种模式采用完全不同的回复设置，互不干扰：

- 文本模式：ai不生成任何配音，不参与任何语音合成与播放等待，文字流式输出完立即推进下一环节，零停顿。此模式下ai的回复面向**阅读**优化：可以使用markdown格式组织内容（重点用**加粗**、分点用有序列表），但不要写成带标题层级的书面报告，保持庭审发言的语态。页面底部为输入框交互。
- 语音模式：ai的每句发言实时合成配音并播报，配音音色按角色分配。此模式下ai的回复面向**播报**优化：一律使用自然口语，句子简短，禁止使用任何markdown符号（如**、##、-、数字列表等会被语音引擎逐字读出的符号），禁止使用括号描述神情动作。页面底部为"按住说话"交互（按住录音、松开发送，语音识别一律走服务端ASR接口，严禁使用浏览器Web Speech API）。
- 模式切换按钮随时可点，切换时立即打断当前正在播放的配音，下一轮发言即按新模式的设置生效。

## 流式输出与配音的工程要求（务必遵守，否则会出现严重卡顿）

- 所有llm流式接口走SSE协议（`data: {"content":"..."}` + `data: [DONE]`），服务端逐chunk立即转发，**严禁在任何SSE路由中加入人为的sleep/减速代码**（大模型原生生成速度就是最佳的打字机节奏，人为减速会把3000字长文拖慢近1分钟）。
- 前端渲染流式文本时必须做**节流**（约50ms一档批量setState，20fps人眼已完全流畅），禁止每个chunk都全量setState触发ReactMarkdown整篇重解析，否则长文本后期主线程被渲染占满。
- 语音模式的配音采用**分句流水线+预取管线**：流式输出过程中按句末标点（。！？；）即时切句送入TTS队列，TTS合成（并发窗口3）与音频播放解耦——播放第N句时第N+1~N+3句已在后台并行合成完毕，语音一句接一句无缝播报；合成失败的句子跳过不阻塞；用户发言/跳过/切换模式时打断全部在途合成与播放。
- 阶段推进**不被配音播放进度阻塞**：文字阶段推进最多只在语音积压超过约8句（≈30秒）时限速，正常节奏下恒为零等待——上一个发言文字流完约0.3秒内即显示下一个"ai正在思考"。
- ai扮演角色的发言长度分级：公诉人或辩护人发表实体性意见（公诉意见、辩护意见、质证意见等）时必须充分展开（120-300字、可分点论述）；其余角色及程序性回应保持简洁。不要给所有角色写一刀切的字数上限。

# 美观

设计背景、字体、字号三个下拉选择框（放在标题栏）。背景设置5种完全不同的风格，不要纯黑色，风格和文字颜色要一起切换，对比度和柔和度合理，保证可读性：清雅白、暖阳米、森林绿、藏蓝韵、古韵宣（均为淡色底+深色字，意象分别为法庭晨光、图书馆午后、法庭木饰、专业信赖、竹简法典）。可以设置字体，雅黑、黑体、宋体三种，默认雅黑；字号设小/中/大/特大4档，字体字号可以影响到画面中的所有字。主题、字体、字号通过html的data-theme/data-font/data-fontsize属性切换CSS变量实现，并持久化到localStorage；在首帧渲染前用预绘脚本同步读出并设置到html属性上，杜绝刷新时的主题闪烁。

# 技术栈与工程规范

- Framework: Next.js (App Router) + React + TypeScript (strict)，UI组件用shadcn/ui，样式用Tailwind CSS，全局状态用Zustand（persist持久化主题/字体/字号/配音开关/用户/文书/学习进度等，选中案例与对话记录为内存态）。
- 数据库用Supabase (PostgreSQL) + Drizzle ORM，浏览器不直连数据库，所有数据访问走服务端API路由。
- ai能力：大模型走豆包 doubao-seed-2-0-pro（关闭推理）；语音合成TTS与语音识别ASR走服务端API（ASR只接受16kHz单声道WAV，录音blob需在前端转换后base64上传）。
- 长耗时生成走Coze平台工作流：异步执行+轮询历史记录获取结果，页面刷新后可断点恢复。
- useSearchParams必须包在Suspense边界内；严禁在JSX渲染逻辑中直接使用typeof window、Date.now()、Math.random()；严禁非法HTML嵌套。
- 所有需要读取全局store的组件，订阅时必须有selector或保证不因无关字段变化而重渲染；给hooks传数组参数时禁止传内联字面量数组（每次渲染新引用会导致effect循环写store，引发"Maximum update depth exceeded"整页白屏），必须传模块级稳定常量。

# 登录界面

- 左面为一个好看的html动画，并有模拟法庭的广告词，右边为登录窗口。
- 学生实名登录走**超星统一身份认证OAuth单点登录**：点击学生登录按钮直接跳转超星授权页（机构fid取服务端白名单第一项；白名单配置多个机构时，按钮下方提示"将跳转超星统一鉴权登录，支持：…"动态列出全部单位名，不硬编码机构）。授权回调后服务端换取token、按token查询用户身份（首选passport统一接口获取真实单位dxfid按白名单校验，失败时回退泛雅用户库接口在白名单内逐机构重试），取学工号和姓名，落students表建立/同步账号，再建立服务端会话（httpOnly Cookie），经/auth/complete页同步前端store后进入目标页。可信身份只读服务端的app_metadata（学工号、姓名、students.id），user_metadata只能展示。
- 学生端登录窗口下，可以输入密码并点击教师端按钮进入教师端，密码为123（环境变量TEACHER_PASSWORD）。教师端为双门槛：先校验教师密码，服务端把教师意图写入HMAC签名的登录上下文；再走超星OAuth，回调建会话时凭签名上下文把账号角色持久提升为teacher。绕开密码直接拼教师端地址拿不到签名标记，会被教师端守卫弹回。
- 学生端可以修改个人信息，包括上传头像jpg（默认为随机分配的纯色表情）、修改昵称（默认为未知用户）。
- 设置免登录的游客学生：点击游客访问即建一条is_guest记录进入系统，无服务端会话。

# 通用页面设计

- 所有功能按钮，都必须放在标题栏，包括学生扮演的角色、卷宗、法条检索、背景、字体、字号、跳过、继续、文书、学习记录、结束分析、首页。
- 任何页面，点击跳过都可以无条件跳过当前环节进入下一环节/下一页（跳过前打断全部配音与在途流式请求）。
- 继续的按钮，必须满足一定条件才可以点击（否则点下去后弹出相应的提醒），不同页面的继续按钮，必须绑定不同的逻辑链路，不能共用一个逻辑。点击继续按钮后，ai会根据本页学习过程（包括对话）和相关资料（具体情况具体分析），来概括学习过程，并给出评价和训练建议，并在弹窗中展示本页学习过程（包括对话）、本页学习过程的概括、评价和训练建议，这些内容要同步更新在标题栏的学习记录里。之后点击弹窗上的确定，则进入下一页。**总结内容必须流式输出**（ SSE协议，模型按【概括】【评价】【建议】【得分】分隔标记协议输出，前端逐chunk增量解析渲染；弹窗四区块固定渲染、内容在各自框内增长，版面不跳动），且环节级总结要限制字数（概括≤60字、评价≤100字、建议≤60字），打开弹窗即见文字流入。
- 学习记录里清晰记录用户的全部学习过程（包括对话）、各个学习过程的概括和各个过程的评价和训练建议，可以滚动查看，也可以以各个过程的名字为菜单来点击跳转。
- 文书存储角色的对应文书，公诉人为刑事起诉书和公诉意见书，辩护人为辩护词，审判长为庭审提纲；宣判后判决书也存入文书。
- 结束分析按钮在训练任何时刻可点：ai对到目前为止的全部学习过程做流式总结（概括/评价/建议/得分，不限字数），展示本次学习时长，确认后保存学习场次并返回首页。
- 法条检索按钮（首页除外各页可用）跳转法条检索整页：输入关键词触发工作流7674184725792489498（异步+轮询），输出为相关法条law数组与解释/案例explain数组（{point, content}结构）；结果区左栏为法条卡片列表、右栏为按〔N〕序号分组的解释两层折叠目录；点击法条进入详情视图，法条正文与解释均**直出渲染**（原文已在数据库中优化好，零LLM请求，本地符号解析+markdown渲染）；页面为全宽版式，外层框架固定不滚、双栏结果区各自独立滚动。
- 学习行为轨迹：各庭审页在ai发言的流式输出中会夹带LIFECYCLE标签（如`<LIFECYCLE>进入法庭辩论</LIFECYCLE>`），前端在渲染和配音入队时剥离该标签（含流式中的半截标签），并把标签内容作为生命周期行为记录保存到学习场次，供教师端回溯学生操作与流程轨迹。

# 模拟法庭辩论主页面设计

- 不论用户选择何种角色，在法庭调查、法庭辩论、被告人最后陈述、宣判、宣布闭庭各环节，分别采用三种角色的特色配图，在每个人物的身边加上对话气泡，到他发言的时候闪亮一下。
- 背景图在画面右面，由用户做语音或文字交互，画面左面为卷宗。以案件基本资料case、诉讼文书卷plead、询问笔录record、证据材料evidence为一级菜单，除了案件基本资料不设二级菜单，其他各自Array<Object>下的各title为二级菜单，对应的各自Array<Object>下的各book为菜单下的具体内容，这样就方便查看卷宗了。
- 语音文字交互可以切换，当使用文字交互时，ai也不生成各音色的声音，而是直接输出文字（详见"文本/语音双模式"）。
- 在语音模式下，在画面中间上方显示：发言角色正在发言…，且多角色庭审页的等待气泡必须显示"{当前发言角色}正在思考…"（等待期正确归属公诉人/辩护人等，而不是卡在审判长）。在文本模式下，ai生成的对话的格式为：

  发言角色：

  发言内容

- 设置一个下一环节的按钮，在需要用户ai交互的环节中，点击此按钮时，可以跳过需要用户交互的环节，进入到下一环节，可能为旁白、全ai对话或者下一个用户与ai交互的环节，根据具体情况而定。
- 各庭审页右下角挂流程提示悬浮框（提示当前环节任务），可自由拖拽、20秒自动关闭。

# 教师端

- 教师端主页为学情区与案例设计区同页的两列网格布局（桌面端）：左列上方为设计模拟法庭案例区、下方为案例结果列表；右列自上而下依次为训练学情、学习场次统计、学生总览统计三张卡片，案例列表与学情表等宽；移动端单列按顺序堆叠。五张卡片的头部均为单行紧凑布局（标题+描述同行，统计类卡片右侧挂"查看详情"按钮开全量列表弹窗），表格行高紧凑，保证1080p特大字号档下各表至少展示5行。
- 设计模拟法庭案例区：输入案例设计需求后，点击确定，触发id为7656623831193223210的工作流，以案例设计需求need为输入，工作流的输出为案例名name、案件基本介绍profile、训练价值teach、案件基本资料case、诉讼文书卷plead、询问笔录record、证据材料evidence、相关法条和司法解释law。该工作流为异步执行（约10分钟），采用提交后轮询历史记录的方式获取结果；因工作中断（如关闭页面）导致结果未落库的案例，再次进入教师端时自动断点恢复（检查"正在生成"状态的案例并继续轮询落库）。
- 工作流的展开结果这样查看：点击结果列表后，进入到案例详情查看页，分为左中右三栏：详情查看页左栏同步展示案例名name、案件基本介绍profile、训练价值teach；详情查看页中栏上半部分滚动查看案件基本资料case，中栏下半部分滚动查看相关法条和司法解释law，law是由Array<String>类型变量经JSON序列化后转化成的String类型变量，在输出时，需要再经JSON反序列化转化成Array<String>类型变量，并渲染为多个独立文本框；详情查看页右栏诉讼文书plead、询问笔录record、证据材料evidence，他们都是由Array<Object>类型变量经JSON序列化后转化成的String类型变量，渲染时，需要再经JSON反序列化转化成Array<Object>类型变量，你需要注意到其最小单位Object都是由title（字符数少的那个String字段）和book两个String类型变量组成的，那么以诉讼文书、询问笔录、证据材料为一级菜单，各自Array<Object>下的各title为二级菜单，对应的各自Array<Object>下的各book为菜单下的具体内容，这样就方便查看工作流的各项结果了。案例详情查看页内容全部资料都可以修改，title名也可修改，且可以以title为单位来新增二级菜单、给二级菜单排序和删除二级菜单，司法解释law那里可以整块新增、删除和拖动排序。案例详情查看页有保存、发布两个按钮，另有"评分标准"按钮跳转该案例的评分标准大页面。
- 相关法条和司法解释law的质量保障：工作流长输出存在"后半段疲劳"问题（后面的法条只有标题没有正文）。所有law落库的入口（工作流保存、断点恢复、教师手工编辑保存、发布）都必须经过完整性校验：解析JSON数组后，凡条目不含"："或"："后正文不足10字的判定为缺正文，对缺正文条目并行调用大模型按条目类型补全（法条→真实原文；规范文件→核心内容概要；指导案例→案情与要旨），补全失败时保留原文，绝不阻塞保存。

### 弹窗：开庭流程（辩护人和公诉人专属）

根据案件基本资料case，以旁白形式将下面的开庭流程输出在弹窗里，流式输出，宽屏，可滚动查看，需要以对话形式呈现的内容，格式要清晰，正确渲染markdown格式，各方都不申请回避：

- 1.书记员应做的准备工作：开庭审理前，书记员应当依次进行下列工作：（1）查明公诉人、当事人、证人及其他诉讼参与人是否已经到庭；（2）宣读法庭规则；（3）请公诉人、辩护人入庭；（4）宣布全体起立，请审判长、审判员（人民陪审员）入庭；（5）审判长、审判员就座后，当庭向审判长报告开庭前的准备工作已经就绪。注意事项：实践中，在此阶段，书记员应提前到达法庭，了解、配齐法庭设施，如根据被告人、辩护人、被害人人数准备坐椅、摆放桌牌等。
- 2.审判长宣布开庭，传被告人到庭，并查明被告人如下情况：（1）姓名、出生年月日、民族、出生地、文化程度、职业、住址或者单位的名称、住所地，诉讼代表人的姓名、职务等；（2）被告人是否曾受过法律处分及处分的种类、时间，是否被采取强制措施及强制措施的种类、时间；（3）是否收到起诉书副本及收到日期，附带民事诉讼的，附带民事诉讼被告人收到民事起诉状的日期。
- 3.审判长宣布案件的来源、起诉的案由、附带民事诉讼原告人和被告人的姓名（名称）及是否公开审理。对于不公开审理的案件，应当当庭宣布不公开审理的理由。
- 4.审判长宣布合议庭组成人员、书记员、公诉人、辩护人、鉴定人和翻译人员名单。
- 5.审判长告知当事人、法定代理人在法庭审理过程中依法享有如下诉讼权利：（1）可以对合议庭组成人员、书记员、公诉人、鉴定人和翻译人员申请回避；（2）可以提出证据，申请通知新的证人到庭，调取新的证据，重新鉴定或者勘验、检查；（3）被告人可以自行辩护；（4）被告人可以在法庭辩论终结前作最后的陈述。

# 知识库

以下领域知识需要内置为常量（如src/lib/knowledge.ts），供各庭审页的system prompt按角色注入：法庭举证、法庭质证、直接询问、交叉询问、法庭语言、法庭辩论、评议的注意事项、开庭前审判长应完成的工作（参考答案）、开庭步骤、法庭调查的操作步骤、法庭辩论的操作步骤、宣判的操作步骤。其中法庭调查、法庭辩论、宣判、宣布闭庭的操作步骤与注意事项全文如下。

## 法庭调查的操作步骤

- 1. 公诉人宣读起诉书。在审判长宣布法庭调查开始后，首先由公诉人宣读起诉书；有附带民事诉讼的，再由附带民事诉讼原告人或者其诉讼代理人宣读附带民事起诉状。
- 2. 被告人陈述。在审判长主持下，被告人可以就起诉书指控的犯罪事实进行陈述。被告人如果承认起诉书指控的犯罪，应让其陈述犯罪事实；如果他否认起诉书指控的犯罪，应允许他陈述辩解意见。
- 3. 被害人陈述。在被告人陈述之后，如果有被害人，则应在审判长的主持下，由被害人对起诉书指控的犯罪事实及自己的受害经过进行陈述。
- 4. 控辩双方讯问或询问被告人。在审判长的主持下，公诉人，被害人及其法定代理人、诉讼代理人，被告人的法定代理人及辩护人可以讯问或询问被告人。其次序是：（1）公诉人可以就起诉书指控的犯罪事实讯问被告人；（2）经审判长许可，被害人及其法定代理人、诉讼代理人可以就公诉人讯问的情况对被告进行补充性发问；（3）经审判长准许，被告人的辩护人及其法定代理人可以就案件事实向被告人发问。
- 5. 控辩双方询问被害人。在审判长的主持下，控辩双方可以询问被害人。
- 6. 审判人员讯问或询问。审判人员认为有必要时，可以向被告人、被害人发问。
- 7. 询问证人、鉴定人。基于直接和言词原则的精神，只有在法庭上经过控、辩双方询问、质证，证言和鉴定意见才能作为定案的根据。询问证人、鉴定人的顺序是：首先，由审判人员告知他要如实地提供证言和有意作伪证或者掩匿罪证要负的法律责任。其次，先由证据的内容对本诉讼主张有利的一方对证人、鉴定人进行询问。再次，经审判长许可，由对方对证人、鉴定人进行反询问。最后，在控辩双方询问完毕后，合议庭认为有必要时，可以询问证人、鉴定人。在询问的过程中，向证人、鉴定人发问的内容与本案无关或者发问的方式不当的，审判长应当制止；控辩双方认为对方发问的内容与本案无关或者发问的方式不当并提出异议的，审判长应当根据情况予以支持或者驳回。
- 8. 出示实物证据、宣读鉴定意见和有关笔录。公诉人、辩护人应当向法庭出示实物证据，让当事人辨认。当庭出示的实物证据，应当先由出示证据的一方就所出示的证据来源、特征等作必要的说明，然后由另一方进行辨认并发表意见，控辩双方可以互相质问、辩论。对未到庭的证人、鉴定人，其证言笔录及鉴定意见应当当庭宣读。当庭出示的实物证据、宣读的证人证言、鉴定意见和勘验、检查笔录，在出示、宣读后应将原件移交法庭。
- 9. 调取新的证据。法庭审理过程中，当事人和辩护人、诉讼代理人有权申请通知新的证人到庭，调取新的物证，申请重新鉴定或者勘验。当事人和辩护人、诉讼代理人申请通知新的证人到庭，调取新的物证，申请重新鉴定或者勘验的，应当提供证人的姓名、证据的存放地点，说明所要证明的案件事实、要求重新鉴定或者勘验的理由。审判人员对于上述申请，应当作出是否同意的决定。在法庭审理过程中，辩护律师在提供被告人无罪或者罪轻的证据时，认为在侦查、审查起诉过程中侦查机关、人民检察院收集的证明被告人无罪或者罪轻的证据材料需要在法庭上出示的，可以申请人民法院向人民检察院调取该证据材料，并可以到人民法院查阅、摘抄、复制该证据材料。
- 10. 法庭调查核实证据。在法庭调查过程中，合议庭对证据有疑问的，可以宣布休庭，对证据进行调查核实。人民法院调查核实证据的方法有勘验、检查、扣押、鉴定和查询、冻结。必要时，人民法院在调查核实证据时，可以通知检察人员、辩护人到场。
- 11. 以上部分是刑事诉讼部分的法庭调查。附带民事诉讼部分的法庭调查，一般在刑事诉讼部分调查结束以后，根据民事诉讼法的有关规定进行。

## 法庭调查的注意事项：

- 1. 公诉人宣读起诉书时，应该宣读起诉书的全部内容，包括起诉书的落款单位等，但该起诉书的附注部分不必宣读。
- 2. 法庭调查阶段，先由公诉人举证，并接受诉讼各方的质证。在公诉人举证完毕后，被害人及其代理人、被告人及其辩护人可以向法庭提交证据。未经法庭调查并接受对方质证的证据，法院不得作为裁判的根据。
- 3. 在向法庭举证时，可以一次举出一份证据，也可以一次举出一组证据。每举出一份或一组证据，都需要简洁明了地向法庭说明证据的种类、名称、来源、内容及证明目的。
- 4. 讯问、询问需要遵守的规则是：（1） 起诉书指控被告人的犯罪事实为两起以上的，法庭调查时，一般应当就每一起犯罪事实分别进行讯问；（2） 对于共同犯罪案件中的被告人，应当分别进行讯问，合议庭认为必要时，可以传唤共同被告人同时到庭对质；（3） 控辩双方讯问或询问与本案无关的问题的，审判长应当制止；（4） 控辩双方认为对方讯问或者询问的内容与本案无关，或者讯问、询问的方式不当并提出异议的，审判长应当根据情况予以支持或者驳回。
- 5. 被告人当庭翻供的处理。实践中被告人有时会当庭推翻侦查阶段的有罪供述。在被告人翻供后，就公诉人而言，应当沉着冷静，通过宣读侦查阶段犯罪嫌疑人的口供笔录及提出其他证据予以证明。对此，《人民检察院刑事诉讼规则》第403条第2款规定：“被告人在庭审中的陈述与在侦查、审查起诉中的供述不一致，足以影响定罪量刑的，可以宣读被告人供述笔录，并针对笔录中被告人的供述内容对被告人进行讯问，或者提出其他证据进行证明。”就法官而言，则应当通过讯问被告人了解翻供的真实原因；审查翻供的前后说法，查明前后供述的差别之处；变换角度反复讯问，审查翻供的内容与其他证据是否一致。
- 6. 询问证人需要遵守的规则是：（1） 询问的内容应当与案件事实有关；（2） 不得以诱导方式提问；（3） 不得威胁证人；（4） 不得损害证人的人格尊严。这些规则也适用于对被告人、被害人、附带民事诉讼原告人和被告人、鉴定人的讯问或者询问。
- 7. 控辩双方针对对方违法讯问、询问提出异议的程序一般是：（1） 举手示意；（2） 向审判长提出抗议，简洁地说明理由，如对方的询问是诱导性询问等；（3） 合议庭当庭表态异议能否成立。
- 8. 合议庭对被告人、被害人及证人、鉴定人等的发问，只能在控辩双方讯问、询问完毕后才能进行。而且，这种发问是一种补充性发问。当然，为了查明事实真相，审判长、审判员、陪审员也应积极思考，在案件关键事实不清时，应当积极主动发问。
- 9. 所有在法庭上提交的实物证据及复制品，均需由法警当庭传递给对方查看、质证，然后再传给审判人员。实物证据原则上应当移交原物、原件。

## 法庭辩论的操作步骤

- 1. 审判长宣布进入法庭辩论。
- 2. 公诉人发表公诉意见。
- 3. 被害人及其诉讼代理人发言。
- 4. 被告人自行辩护。
- 5. 辩护人辩护。
- 6. 在审判长的主持下控辩双方进行新一轮辩论。
- 7. 审判长宣布法庭辩论结束。

## 法庭辩论的注意事项：

- 1. 刑事审判中的法庭辩论，包括在法庭调查阶段的法庭辩论和专门的法庭辩论阶段进行的辩论。在法庭调查阶段的辩论，经审判长许可，控辩双方可以随时根据案件具体情况进行。在法庭调查后专门的辩论阶段进行的辩论，合议庭认为本案事实已经调查清楚的，应当由审判长宣布法庭调查结束，开始就全案事实、证据、适用法律等问题进行法庭辩论。控辩双方一定要注意区分法庭调查阶段的辩论和专门的法庭辩论阶段的辩论之关系：在法庭调查阶段，控辩双方的辩论主要针对单个证据的真实性、关联性和合法性进行，侧重于单个证据本身；而法庭辩论阶段的辩论，则综合地从事实、证据以及法律适用等方面进行辩论。
- 2. 审判长应当善于抓住双方辩论的焦点和分歧点，将辩论引向深入，对于控辩双方与案件无关、重复或者互相指责的发言应当予以制止。经过几轮辩论后，如果合议庭认为案情已经查明，控辩双方的意见已经充分发表，审判长应当及时宣布辩论终结。
- 3. 在个别案件中，被害人和公诉人的意见可能会有分歧，此时审判长应允许被害人与公诉人之间进行辩论。
- 4. 在司法实践中，法庭辩论阶段公诉人的第一次发言通常称为公诉词（或公诉意见书），辩护人的第一次发言称为辩护词。公诉词的重点内容是：在总结法庭调查的事实、证据和适用法律的基础上集中阐明人民检察院追究被告人刑事责任的意见。辩护词则是辩护人以法庭调查情况为基础，针对控方指控的不实或漏洞之处，说明被告人应当无罪、罪轻、从轻、减轻或者免除处罚的根据和理由，并请求合议庭采纳已方的辩护意见。
- 5. 在法庭辩论过程中发现了新的事实，认为有必要进行调查的，审判长可以宣布暂停辩论，恢复法庭调查，待该事实查清后继续进行法庭辩论。
- 6. 法庭辩论的目的是说服法官，而非辩论者个人单纯地展现自己的才华和争强斗胜。因此，在法庭辩论时，辩论者应当见好就收，不要抓住对方的漏洞穷追猛打。
- 7. 附带民事诉讼部分的法庭辩论应当在刑事诉讼部分的辩论结束后进行，先由附带民事诉讼原告人及其诉讼代理人发言，然后由被告人及其诉讼代理人答辩，随后还可以进行多轮辩论。

## 宣判的操作步骤

- 1. 书记员宣布：全体起立，请审判长、审判员入庭。
- 2. 待合议庭成员坐定后，书记员宣布：请坐下。
- 3. 审判长宣布：现在继续开庭。
- 4. 审判长宣布判决内容，包括认证结论、裁判理由、裁判结果。
- 5. 在审判长宣告最终的裁判结果前，由书记员宣布：全体起立。
- 6. 然后审判长接着宣布最终的判决结果。判决结果宣判完毕，审判长敲击法槌。
- 7. 书记员宣布：请坐下。（全体坐下。）
- 8. 审判长接着告知当事人上诉权并征询当事人意见，即：如不服本案判决，可在判决书送达之日起10日内，向本院递交上诉状，并按对方当事人人数提出副本，上诉至×××法院。上述判决，被告人是否听清楚了？
- 9. 被告人回答。
- 10. 审判长宣布：现在闭庭！（敲击法槌。）

## 宣判的注意事项：

- 1. 宣判分为当庭宣判和定期宣判。当庭宣判的，应当在5日以内将判决书送达当事人、辩护人、诉讼代理人和提起公诉的人民检察院。定期宣判的，应当在宣判后立即将判决书送达当事人和提起公诉的人民检察院。在模拟实验中，建议当庭宣判。
- 2. 案件无论是否公开审理，宣判一律公开进行。
- 3. 地方各级人民法院在宣告第一审判决时，应当明确告知当事人和他的法定代理人上诉的期限和上诉的法院。
- 4. 宣判时，只有在审判长宣布“判决结果”时，才需要全体起立；在宣读判决书前，不需要起立。

## 宣布闭庭的操作步骤

- 1. 审判长宣布：庭审结束。现在宣布闭庭！（敲击法槌。）
- 2. 书记员宣布：全体起立。（目送合议庭成员退庭。）
- 3. 待合议庭成员退庭后，书记员宣布：现在散庭，诉讼参加人和旁听人员退庭。

## 宣布闭庭的注意事项：

在审判长宣布闭庭后，应立即敲击法槌，然后书记员宣布“全体起立”，这三个环节之间应有效地衔接。
