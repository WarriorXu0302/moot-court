# 国际仲裁场景设计文档

> 状态：设计稿（未开工）｜依据：教改课题申报书《人工智能辅助下涉外法治人才培养的实务课程建设》、《中国国际私法经典案例评析》（修订稿）、调研报告（2026年8月）
> 与根目录 `DESIGN.md`（视觉设计）无关，本文只讨论功能与架构。

---

## 1. 目标与定位

在现有刑事模拟法庭系统上扩展**国际商事仲裁**场景，对应课题"研究内容三：AI 支撑的涉外法律实务实训平台"。

- 以跨境商事争议为标准案例，覆盖：仲裁协议效力与管辖权、仲裁庭组成、程序管理、举证质证、证人与专家证人询问、实体法适用、裁决书、裁决的承认与执行。
- **刑事功能保持不变**，仲裁作为新增 `case_type`，存量数据零迁移。
- 不是"换个提示词"：现有庭审页流程硬编码（如 `judge-investigation/page.tsx` 的 13 阶段 `STAGES`），需先做流程数据化抽象。

## 2. 角色映射

内部枚举 `UserRole = 'judge' | 'prosecutor' | 'defender'` **不改**，展示层按案件类型映射，避免迁移 `store`、`learning_sessions`、`training_records` 里的历史数据。

| 内部角色 | 刑事展示 | 仲裁展示 | 学生任务 |
|---|---|---|---|
| prosecutor | 公诉人 | 申请人代理人 | 提出仲裁请求、举证、论证 |
| defender | 辩护人 | 被申请人代理人 | 答辩、管辖权异议、反请求 |
| judge | 审判长 | 首席仲裁员 | 主持程序、程序令、合议、裁决书 |

AI 扮演：对方代理人、两位边裁（合议）、事实证人、**专家证人**、仲裁秘书（对应书记员）。

## 3. 首个标准案例

**恒基公司、北大青鸟诉广晟投资案**（最高人民法院（2006）民四终字第28号，公报2008年第1期），来源：《中国国际私法经典案例评析》第十六章案例2。

选它的理由：
- 争点单一：涉外仲裁协议效力的准据法。
- 双方立场对抗清晰，适合 AI 扮演双方代理人。
- 书中法理分析给出完整逻辑框架，可直接作为评分"标准答案"：
  1. 当事人明确约定仲裁协议准据法 → 适用该法；
  2. 未约定但约定仲裁地 → 适用仲裁地法；
  3. 均未约定或约定不明 → 适用法院地法。
  4. 关键点：合同中"解决合同争议适用的准据法"不能直接作为仲裁条款效力的准据法。
- 附带拓展案例（Enka v Chubb [2020] UKSC 38 等）可用于"外国法查明"、类案检索训练。

候选后续案例：

| 案例 | 争点 | 适合环节 |
|---|---|---|
| 江苏轻纺诉裕亿、太子案 | 仲裁条款独立性；欺诈侵权可仲裁性；仲裁第三人 | 管辖权异议 |
| Hemofarm 诉济南永宁案 | 外国仲裁裁决承认执行；公共政策；超裁 | 评议、裁决书、承认执行 |

第二期"涉外民事诉讼"路线的素材：同书第十五章（不方便法院、互惠原则、承认外国判决条件等 4 个案例）。

> **版权与版本风险**：该书为出版物，且文件头部有"修改校对分组"，为修订稿。内置为系统案例前需确认授权与最终版。

## 4. 数据模型

### 4.1 `cases` 表新增字段

```ts
case_type: varchar("case_type", { length: 20 }).notNull().default("criminal"),
// 'criminal' | 'arbitration'；涉外诉讼、调解预留
meta: jsonb("meta"),
```

仲裁 `meta`：

```ts
interface ArbitrationMeta {
  rules: 'CIETAC' | 'ICC' | 'HKIAC' | 'UNCITRAL';
  seat: string;            // 仲裁地
  governingLaw: string;    // 实体准据法
  language: 'zh' | 'en' | 'bilingual';  // 第一期仅 zh
  claimAmount: string;
  issues: { id: string; title: string; type: 'jurisdiction'|'merits'|'quantum'|'procedure' }[];
}
```

### 4.2 复用现有列，仅改语义

| 现有列 | 刑事 | 仲裁 |
|---|---|---|
| `indictment` | 起诉书 | 仲裁申请书 |
| `defense` | 辩护词 | 答辩状（含反请求） |
| `prosecution` | 公诉意见书 | 申请人代理意见（Closing） |
| `victim` | 被害人 | 证人 / 专家证人陈述 |
| `plan` | 庭审提纲 | 程序时间表 / 程序令草案 |
| `judge` | 评分标准 | 评分标准（不变） |
| `law` | 司法解释 | 仲裁规则、条约、准据法条文 |

读取侧统一经 `src/lib/case-type.ts` 的 `getCaseLabels(caseType)` 提供文案，页面不再写死。

### 4.3 兼容性

- 存量案例默认 `criminal`，行为零变化。
- 迁移前必须先核对 `learning_sessions` 表：`schema.ts` 中**没有**该表定义（仅 `api/learning-sessions/route.ts` 直接使用），第三期前需补齐 Drizzle schema。

## 5. 核心重构：流程定义数据化（第 0 步）

### 5.1 问题
6 个调查/辩论页各 600~700 行，STAGES、systemPrompt、AI 响应逻辑耦合。为仲裁再复制三套，AGENTS.md 中记录的坑（`userInteractedRef` 假死、`responder` 漏配）会重踩。

### 5.2 目标结构

```
src/lib/flows/
  types.ts         // StageDef, FlowDef
  criminal.ts      // 现有 STAGES 原样搬出
  arbitration.ts   // 新增
  index.ts         // getFlow(caseType, role, phase)
```

```ts
interface StageDef {
  id: string;
  label: string;
  type: 'ai' | 'interactive';
  speaker: string;
  responder?: string;   // AI 发问阶段必须配置（沿用既有约束）
  hint?: string;
  promptKey?: string;
}
```

### 5.3 实施策略
先**只抽数据，不动页面逻辑**：`STAGES` 搬到 `flows/criminal.ts`，页面改为 `getFlow(...)`；刑事回归通过后，仲裁复用同一套页面。与刑事强相关的 systemPrompt 改由 `flows/*` 提供。

## 6. 仲裁流程

### 6.1 首席仲裁员路线
案情研读 → 仲裁庭组成与程序审查 → 程序令撰写 → 开庭 → 调查（举证质证）→ 辩论 → 评议（合议）→ 裁决书 → 宣布裁决与闭庭

### 6.2 申请人 / 被申请人路线
案情研读 → 仲裁申请书 / 答辩状撰写 → 开庭陈述 → 举证质证与证人询问 → 结案陈词 → 裁决宣布

### 6.3 调查阶段表

| 阶段 id | 内容 | 类型 | 说话人 → 回应者 |
|---|---|---|---|
| `opening_remarks` | 宣布开庭，核实仲裁庭组成、回避 | 交互 | 首席 |
| `jurisdiction_objection` | 管辖权异议（仲裁协议效力） | AI | 被申请人 → 申请人 |
| `tribunal_ruling_juris` | 仲裁庭就管辖权作初步意见 | 交互 | 首席 |
| `claimant_opening` | 申请人开庭陈述 | AI | 申请人 |
| `respondent_opening` | 被申请人开庭陈述 | AI | 被申请人 |
| `evidence_claimant` | 申请人举证 | AI | 申请人 |
| `cross_claimant_evidence` | 被申请人质证（三性） | AI | 被申请人 |
| `witness_exam` | 事实证人询问（直接+交叉） | AI | 申请人 → 证人 |
| `expert_exam` | 专家证人询问（损失计算、外国法） | AI | 被申请人 → 专家 |
| `tribunal_questions` | 仲裁员提问 | 交互 | 首席 → 当事人 |
| `evidence_respondent` | 被申请人举证及质证 | AI | 被申请人 |
| `closing_procedure` | 宣布调查结束 | 交互 | 首席 |

### 6.4 辩论阶段
申请人 Closing → 被申请人 Closing → 各方费用承担陈述。

> 以上阶段为**初稿**，须由课题组按 CIETAC/ICC 实际程序校准后定稿。

## 7. AI 发言风格与提示词

新建 `src/lib/arbitration-style.ts`，导出 `ARB_INVESTIGATION_STYLE` 与 `ARB_DEBATE_STYLE`，在仲裁页 systemPrompt 末尾注入（沿用 `court-style.ts` 方式）。

| 角色 | 风格（初稿，待校准） |
|---|---|
| 首席仲裁员 | 程序语言克制，用"本庭"，程序性短句；提问点明争议焦点 |
| 代理人 | 开庭陈述 200~400 字分点（请求权基础、事实、法律）；质证按三性加关联；不情绪化 |
| 证人 | 事实直答，不用法律术语 |
| 专家证人 | 可用专业术语，区分事实与意见，接受方法论质疑 |

**必须遵守的既有约束（AGENTS.md）**：
- 单次发言只扮演一个角色；
- 所有"AI 发问"阶段必须配 `responder`；
- `responder` 回答完成、推进下一阶段前必须复位 `userInteractedRef.current = false`；
- 新页面必须注入对应 SPEECH_STYLE，不写一刀切字数上限；
- `useStageDialogueLogger` 只能传模块级稳定常量，禁止内联数组；
- 禁止在 SSE 路由加人为 sleep；
- 流式循环统一使用 `createThrottledStreamSetter`；
- TTS 仅在语音模式生成，走分句流水线。

语言：**仅中文**（2026-11-18 确定，不做英文界面、英文 AI 回复或双语案例；原「双语放第四期」的规划搁置）。`meta.language` 字段保留但固定为 `zh`。

## 8. 文书与评分

### 8.1 文书页
复用写作页骨架（对话 / 编辑 / 评价三栏）：

| 文书 | 复用页 | 评价要点 |
|---|---|---|
| 仲裁申请书 | `indictment-writing` | 当事人、仲裁协议、仲裁请求、事实与理由、证据清单 |
| 答辩状（含反请求） | `defense-writing` | 管辖权异议、实体抗辩、反请求依据 |
| 裁决书 | `judge-deliberation` 判决书栏 | 争议焦点归纳、事实认定、法律适用、裁决主文、费用 |

写作页 600~1000 行，**先让标题与评价提示词配置化注入，不做页面级重写**。

### 8.2 评分标准
`scoring.ts` 结构（overall + stages + sampleUnlock）不变，新增：
- `buildScoringGenerationPrompt(caseType)`，仲裁版维度：管辖权论证、证据运用、法律适用与外国法查明、程序意识、专家证据处理、文书质量；
- 种子文件 `scripts/scoring-seed-arbitration.json`；
- `migrate-scoring.mjs` 按 `case_type` 区分，避免给仲裁案例补刑事标准；
- **横向维度"AI 应用四力"**：操作力、核查力、创新力、防控力（来自高校人工智能法律实训联盟，2026-06 成立大会）。其中"核查力"在仲裁场景具体为：核查 AI 给出的条约条款、裁判案例是否真实存在。
- 首个案例（恒基案）的"仲裁协议准据法三层逻辑"写入管辖权环节评分要点。

## 9. AI 使用披露与留痕（第二期）

参照调研报告中的境外做法：
- 芝加哥大学诊所：学生披露 AI 使用，全班共同审查 AI 输出；
- 杨百翰大学：技能课程可要求提交工具名称、完整提示词与完整输出；
- 华盛顿大学圣路易斯分校：检索课要求识别幻觉、比较人工检索/通用大模型/专业法律 AI 并核验。

系统实现：
1. 复用 `useStageDialogueLogger` 已采集的对话，提交文书时附"AI 使用说明"；
2. 教师端可查看每份文书对应的 AI 对话与"AI 样例查看次数"；
3. 学习场次增加"AI 辅助程度"指标（学生原创输入占比等，口径待定）；
4. 引用核验：扩展 `law-quality.ts`，对条约条款号、判例存在性做核验，界面显示"已校验 / 未校验 / 教师已审核"。

## 12. 分阶段与验收

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| 0 | 抽 `flows/criminal.ts`，页面改读配置 | 刑事全路线 e2e 无回归，逐阶段行为一致 |
| 1 | `case_type` 迁移、教师端类型选择、选案页筛选 | 存量案例仍为刑事；可新建并保存仲裁案例 |
| 2 | 首席仲裁员路线（调查、辩论、评议），首案恒基案 | 阶段自动链跑通，所有 responder 生效，无假死 |
| 3 | 申请人 / 被申请人路线 + 文书页 | 3 类文书可写、可评价 |
| 4 | 评分标准、学情、AI 使用披露、导出 | 教师端可见仲裁场次、得分、AI 使用记录 |
| 5（后续） | 涉外民事诉讼路线、谈判调解、双语 | 另行立项 |

## 13. 对标与参考（调研报告）

- 高校人工智能法律实训联盟（2026-06，92 家高校）：以脱敏真实电子卷宗拆成阶段任务，学生选角色全流程训练，教师端有错题统计与教学分析报告。
- 山东大学"法源"虚拟仿真实训平台：已含国际商事仲裁模块。
- 华侨大学：民诉模拟法庭中学生使用 AI 做证据分析、文书生成、庭审风险预判。
- 密苏里大学堪萨斯城分校 MootMentorAI：AI 个性化口头辩论教练（评价标准稳定性需教师监督）。

本系统差异化：**多角色 AI 对抗 + 语音交互 + 评分标准联动 + 过程留痕**。

## 14. 风险与待决事项

1. **法律内容准确性**：仲裁规则条文、管辖标准、程序时限，AI 易编造。`arbitration-knowledge.ts` 仅搭结构，**条文内容由课题组提供或审核**——这也正是课题"AI 幻觉防控"的实践。
2. **案例素材版权与版本**：见第 3 节。
3. **Coze 工作流**：需用户在平台新建仲裁案例设计、文书生成工作流，并提供 ID。
4. **合议机制**：首席 + 两位边裁，拟复用评议页"陪审员甲乙"机制，待确认。
5. **第 0 步重构**工作量最大，但不做则后续成本更高；必须刑事回归通过后再推进。
6. **阶段表与风格档位**均为初稿，须课题组校准。
